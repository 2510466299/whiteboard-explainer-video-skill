# 动态时长手绘讲解视频 Skill 设计

## 目标

创建一个项目级编排型 Skill：`whiteboard-explainer-video`。它把现有的非文字手绘渲染、内容驱动分镜、连续配音、ChatCut 字幕和验证流程整合为一个可重复调用的工作流。

该 Skill 不重新实现 `whiteboard-video-engine` 或 ChatCut 能力，只负责选择正确工具、传递产物、执行质量门和清理中间文件。

## 核心决策

- 使用一个用户可见的 Skill，而不是两个互相交接的 Skill。
- Skill 提供 `full`、`render-only`、`post-only` 三种运行模式。
- 不设置 150 秒默认时长。150 秒只是已有案例的结果。
- 最终时长以实际旁白音频为主要依据，并结合画面复杂度和换页停顿计算。
- 默认保护图片中的文字，只描画和上色非文字区域。
- 默认交付可编辑的 ChatCut 时间线；只有用户明确要求时才导出最终 MP4。

## 触发范围

当用户希望把一张或多张知识图解、海报、漫画页或分镜图片制作成带手绘过程的讲解视频时使用，尤其适用于以下要求：

- 图片中的文字保持原样，不参与线稿生成或手绘动画；
- 旁白讲完一页时，该页绘制和上色也接近完成；
- 根据内容自动决定总时长；
- 需要连续配音、中文字幕、ChatCut 可编辑项目或最终视频。

不用于纯文字排版动画、真人口播剪辑、无手绘效果的普通图片轮播或仅生成单张插画。

## 输入契约

### 必需输入

1. 视觉素材，满足以下任一种形式：
   - 一张图片；
   - 有明确顺序的多张图片；
   - 一个包含分镜图片的目录。
2. 旁白来源，满足以下任一种形式：
   - 已有逐页口播稿；
   - 已有完整口播稿，并允许 Skill 拆分到各页；
   - 用户允许 Skill 根据图片内容起草口播稿。

### 可选输入

- `mode`：`full`、`render-only` 或 `post-only`，默认 `full`。
- 配音服务、音色、语速、情绪和语言；不得把“大壹 dayi”硬编码为全局默认，但可以在用户已明确选择时复用。
- 目标总时长、最短时长或最长时长；均为可选约束。
- 画面比例、分辨率和帧率；缺省时继承素材或项目设置。
- 字幕开关和样式；`full` 模式默认添加原语言字幕。
- 是否导出；默认不导出。
- 文字策略；默认 `preserve-text`，只有用户明确要求时才能改为描画文字。
- 已有 ChatCut 项目或时间线；未提供时创建或选择新的工作位置。

### `post-only` 的额外必需输入

- 已生成的手绘底片；
- 分镜时间表，或者能够重建分镜边界的逐页音频与页面顺序。

## 输出契约

### 持久化本地产物

`full` 模式默认保留：

```text
<任务目录>/
├── narration.md
├── timing.json
└── whiteboard_base.mp4
```

- `narration.md`：最终逐页口播稿，是后续重配音和字幕纠错的文本依据。
- `timing.json`：每页的图片、旁白、绘制、上色、停留和换页时间。
- `whiteboard_base.mp4`：不烧录字幕的手绘画面底片，可供后期重新配音。

只有用户明确要求导出时，才额外保留：

```text
final_narrated_subtitled.mp4
```

### ChatCut 交付

`full` 和 `post-only` 模式返回：

- ChatCut 项目及可编辑时间线链接；
- 时间线名称、总时长、分辨率和帧率；
- 旁白轨道和字幕状态；
- 抽帧验证结果；
- 未验证项和临时文件清理记录。

### 各模式差异

| 模式 | 输入重点 | 输出重点 |
| --- | --- | --- |
| `full` | 图片和旁白来源 | 口播稿、时间表、手绘底片、可编辑 ChatCut 时间线 |
| `render-only` | 图片，以及明确时长或逐页音频 | 时间表和手绘底片，不生成配音字幕时间线 |
| `post-only` | 已有底片、时间表、口播稿和音色 | 同步旁白、字幕和可编辑 ChatCut 时间线 |

## 动态时长规则

### 权威时间来源

1. 用户提供的实际音频优先级最高。
2. 只有口播稿时，先生成逐页或逐章 TTS，再读取真实音频长度。
3. 字符数估算只用于生成前预判，不能作为最终时间线依据。

### 每页时长

每页基础时长由实际旁白时长决定，并加入 `0.4–1.0` 秒自然停留或换页余量。若画面元素较多，可延长绘制阶段；若用户设置总时长上下限，则在不截断旁白的前提下调整语速、停留和绘制速度。

每页内部节奏遵循：

1. 开始旁白后进入线稿绘制；
2. 线稿完成后进入上色；
3. 上色完成点应尽量落在旁白结束前后 `0.5` 秒内；
4. 旁白结束后保留短暂停顿，再切换下一页；
5. 文字从页面出现起就保持清晰，不经过错误线稿重建。

若无法同时满足旁白完整、画面可读和用户时长上限，必须把冲突报告给用户，不能静默加速到不可理解。

## 工作流

### 1. 预检

- 确认图片数量、顺序、尺寸和可读性。
- 检查是否已有口播稿、音频、旧底片或 ChatCut 项目。
- 建立明确的任务临时目录并记录路径。
- 识别文字密集页面，默认启用文字保护。

### 2. 口播与配音

- 保留用户已有稿件，不擅自改变事实和立场。
- 需要起草时，按页面生成一页一主题的旁白，并在付费 TTS 前让用户确认文本和音色。
- 生成或读取实际旁白音频，测量每页时长。
- 多段音频在时间线上连续排列；章节边界和页面边界对齐，不留下意外空白。

### 3. 时间规划

- 生成 `timing.json`。
- 根据音频长度和非文字画面复杂度分配绘制、上色、停留和转场时间。
- 在渲染前检查总时长、页面边界和音频覆盖范围。

### 4. 非文字手绘渲染

- 调用项目内 `whiteboard-video-engine` 或其 CLI。
- 文字区域使用原图内容或保护遮罩，不把 OCR/线稿结果当作最终中文字形。
- 仅让人物、图标、箭头、框线、装饰和其他非文字视觉元素经历绘制及上色过程。
- 生成不烧录字幕的 `whiteboard_base.mp4`。

### 5. ChatCut 后期

- 导入或复用底片和旁白资产。
- 按 `timing.json` 对齐页面、音频和换页。
- 字幕只绑定实际旁白轨道，不读取画面文字或其他无关音轨。
- 字幕采用适合中文的字体、两行以内分页、描边或半透明底色。
- 对专有名词、英文模型名和明显 ASR 错误做显示文本修正，不改变原音频。

### 6. 验证

- 核对时间线总长与旁白覆盖范围。
- 检查每个换页点附近是否出现音画错位或无声空白。
- 抽查开头、每章中段、页面切换点和结尾。
- 检查文字是否保持原样、非文字是否具有真实绘制过程、字幕是否遮挡关键信息。
- 用户要求导出时，导出完成后再检查实际成片文件。

### 7. 清理与汇报

- 删除本次创建的抽帧、截图、缓存、诊断日志、临时音频切片和测试导出。
- 不删除用户原素材、最终口播稿、时间表、手绘底片、明确要求的导出文件或 ChatCut 项目资产。
- 汇报创建、删除和最终保留的文件及原因。

## 失败处理

- 图片顺序不明确：停止渲染并请求顺序，不自行猜测。
- 文字保护无法可靠识别：先输出代表页预览或请求文字区域说明，不能继续批量生成有瑕疵的文字线稿。
- TTS 失败或音色未确认：不提交额外付费生成，不用未知音色替代。
- 实际旁白超过用户时长上限：优先报告冲突并调整稿件或语速，不截断语句。
- ChatCut 转写未就绪：等待转写完成后再启用字幕。
- 抽帧发现遮挡或错位：修正后重新抽查受影响帧，不直接宣布完成。
- 导出未被用户明确要求：停在可编辑时间线，不消耗导出资源。

## Skill 文件结构

```text
skills/whiteboard-explainer-video/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── input-output-contract.md
    ├── timing-manifest.md
    └── verification-checklist.md
```

首版不复制模型权重、FFmpeg、项目素材或 `whiteboard-video-engine` 源码，也不创建 README、安装指南或变更日志。

## 验收标准

1. Skill 的描述能在“图片转手绘讲解视频、非文字手绘、配音同步、字幕”等请求下正确触发。
2. `full`、`render-only`、`post-only` 的必需输入和输出没有歧义。
3. 默认时长由实际旁白决定，文档中不存在固定 150 秒假设。
4. 默认保护文字，只描画非文字元素。
5. TTS、ChatCut 导出等可能产生费用或外部产物的动作具有明确授权边界。
6. 默认交付可编辑时间线，导出需要明确请求。
7. 字幕只读取旁白轨道，并包含专有名词纠错与视觉验证步骤。
8. Skill 能按需读取三份 reference，而不把全部细节堆入 `SKILL.md`。
9. Skill 包通过结构验证，`agents/openai.yaml` 与 `SKILL.md` 一致。
10. 验证过程不下载模型、不重新生成付费配音或最终成片。
11. 本次创建的临时文件和目录在任务结束前完成清理并汇报。
